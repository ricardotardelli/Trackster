General rules

- Never invent DBC information or unsupported meanings.
- Never infer signals that were not requested.
- If uncertain, classify the signal as generateBehavior=false.

Behavior classification

Use generateBehavior=true only for measurable physical quantities that naturally evolve during normal vehicle operation, including:

- driver inputs
- steering dynamics
- braking dynamics
- powertrain dynamics
- vehicle motion
- suspension dynamics
- electrical propulsion
- thermal behavior
- externally observable physical outputs directly caused by those quantities (for example BrakeLights)

Use generateBehavior=false for:

- protocol fields
- counters
- rolling counters
- checksums
- CRC
- alive fields
- timestamps
- reserved fields
- padding
- commands
- requests
- configuration
- calibration
- initialization
- limits
- setpoints
- modes
- states
- status signals
- controller outputs
- ECU internal logic
- software decisions
- dashboard or HUD information
- user-interface signals
- diagnostic information
- faults
- warnings
- availability flags
- enable flags

Controller-specific representations

When both a generic physical signal and a controller-specific representation of the same physical quantity are present, prefer the generic physical signal.

Example:
   VehicleSpeed → generateBehavior=true
   LKASVehicleSpeed → normally generateBehavior=false

Dependency
dependency represents an immediate physical cause only.
Use dependency=null whenever uncertain.
Never create:
- self-dependencies
- circular dependencies
- reversed physical dependencies
- dependencies on protocol, command, configuration, status or diagnostic signals

Use this physical direction whenever applicable:

Driver Input
→ Torque / Brake Pressure
→ Motor Current
→ Motor Speed
→ Wheel Speed
→ Vehicle Speed
→ Derived Physical Quantities

Typical examples:
   MotorTorque → AcceleratorPedal
   BrakePressure → BrakePedal
   MotorCurrent → MotorTorque
   MotorSpeed → MotorCurrent
   WheelSpeed → MotorSpeed
   VehicleSpeed → WheelSpeed
   ElectricalAngle → MotorSpeed
   Never invert this chain.
   BatteryVoltage and BatteryPercentage should normally use dependency=null unless another requested signal is clearly their immediate physical cause.
